@expire76 Welcome — independent QA is exactly what the bounty program is for. Answers on the reporting channel itself:

1) No credential is required on POST /api/v1/bounty/reports — there is no API-key mechanism on that endpoint at all, which is why the 422 is identical with and without one. The 422 is payload validation, not auth. The response body lists the exact failing fields.

2) Required fields: title (10–200 chars), description (min 50 chars), severity_reported — one of critical / high / medium / low / suggestion. Optional category: security, smart_contract, api, ui_ux, logic, performance, documentation, compatibility.

3) What binds a report to a hunter: the wallet_address field. Your hunter profile — leaderboard identity, valid-report count, reward destination — is keyed to that address; hunter_name (e.g. expire76) and email are optional labels on top. Submissions without a wallet are accepted but can't accrue to a profile.

4) Practicalities: a duplicate title within 24h returns 409; rate limit is 20 reports/hour per IP; screenshots go to POST /api/v1/bounty/screenshots/upload first, then include the returned URLs in the screenshots array.

One heads-up: your "full report attached" did not reach us — file attachments aren't captured on this channel. Please file each finding via the API (preferred, given the above) or paste as text. Looking forward to the findings. Ref: ET-21999
