# For the spec, beyond what the mockup shows

What the live /company cannot do today and the spec has to ask for. One line each; add as they turn up.

- **Departments cannot hand work to each other.** A task's origin is only owner, manager or system (company answers of 2026-10-13), so a process like "a bug found anywhere goes to QA" or "a new build goes to QA for testing" runs only if the Manager routes it. The spec asks for owner-set processes: *when* an event happens, *which* department does *what*, chained, each with an optional human review before it starts or on its result, by the owner or a named person (Processes tab in the mockup). Noted 2026-10-16.
- **Testing becomes "Cymetica QA", the bug bounty as a department.** Its charter files each verified bug straight into the bug tracker under the owner's hunter name and wallet (no approval, the way an outside QA agent already works), reopens a known bug instead of filing it twice, and re-tests a claimed fix on the same ticket. The ET10 Cymetica pays for accepted bugs is shown lit on the department: in the office, in the rail, in its detail. Noted 2026-10-17.
- **Every department has a computer that opens its page on cymetica.com.** Cymetica QA: `/leaderboard/bugs` with My Bugs selected; Development and Design: `/leaderboard/features`; the lab: `/my-agents`; a trading desk: `/account`. Today no URL selects My Bugs (the tab is `data-filter="mine"`, read from nothing in the address), so the spec asks for `/leaderboard/bugs?filter=mine`. Noted 2026-10-17.
