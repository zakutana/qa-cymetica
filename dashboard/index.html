The percentage on each card is a different thing

It answers one question: of all the addresses Cymetica publishes for this part of the platform, how many actually answer when you call them? We call each twice — once with no key, once with the API key — and take the better answer:

“Checks” is a different number again. An address answering does not mean the answer is correct. 100% with no checks means “it is alive, and nobody has verified a word it says”.

The bell, in the top corner

It counts incoming answers on our own bug reports that you have not read yet — a status they changed, or a note they wrote back — and nothing else. A number there means they have moved on something we filed.

It comes from their bug tracker, read back over their own API, so it can only ever show something they actually said. That read happens on a sweep, not when this page redraws: the page is where an answer is delivered, never where one is discovered.

Where to start on their side

Cymetica’s own answer to “point an agent at this”, in their words, and the four documents it names:

llms.txt The machine-readable index of what EventTrader exposes and how to use it. Start here.
POST /mcp/v1 The MCP endpoint — the tools themselves. 41 anonymous, 62 with a key.
agent-card.json Google A2A discovery: skills, auth, capabilities.
/fund-builder/api Developer and fund-builder API docs. HTML, and richer than the OpenAPI covering the same ground.

Their four cover discovery, tools and the programmatic surfaces — but not everything they publish. /backtest/api is the same shape of page for the five backtest surfaces, and carries request bodies that openapi-public.json omits.
