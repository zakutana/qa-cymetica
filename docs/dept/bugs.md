The one department that tests, verifies and files (docs/crew-plan.md). Read at the start
of every run. Ten lines a heading at most; the manager curates it once a day, and a line
that stops being true moves to the archive, never silently away. Write with
`python scripts/crew.py lesson bugs --heading know|work|wrong --text "..."`.

## How we work

- A `bug` ticket: reproduce it through our client first; a defect gets a check and a report through `submit.py`, a documentation gap is said to the manager for the operator's Telegram (CLAUDE.md).
- A `sweep` ticket: the qa-sweep skill at narrow width; a `hunt` ticket: their newest surface first, SAFE reads.
- What woke a sweep (`moved` in the ticket) is read before anything else.
- 2026-10-12 Level R needs no prereg and no clean tree: git_dirty and no_prereg block only V (qa/state.py:151-168); R is blocked by fingerprint drift, a legacy schema, results not collected, or an exit status that disagrees. A verdict lists every reason, V's beside R's -- read which list each sits in. When tidy names a path, run at level R and say what it named; 'no sweep at any level' is never the close (T-0002's third try).
- 2026-10-25 A fold leaves its run record staged (`ledger.py --run`, git add -f into the ignored state/runs/): name it in the fold commit beside the ledger, the journal and the page, `scripts/commit.py ... -- state/runs/<id>.json`; commit.py commits an ignored path only when the index already holds it, and tidy counts a staged record as housekeeping (OP-0009). Commit your own lesson in the turn you write it.
- 2026-10-12 2026-10-12 A worker can write tests/repo but not scripts/, qa/ or tests/meta (T-0009): hand a code fix over as a strict-xfail test there that fails on the ASSERTION, not on a missing name, and say which lines the fix must add. A tests/meta test that blocks a sweep is said to the manager and the ticket failed, never worked around (T-0007: never unset QA_CREW_DEPT).
- 2026-10-12 T-0059: a changed check on the SAME nodeid is accepted with withdraw.py pin-fingerprint --from-run <run> (rebind-check moves a row between nodeids; from == to changes nothing). Order: commit, run tests/rest/<file> alone (27 s, level R), pin, ledger.py --run, render; the row then reads REPRODUCING under the new fingerprint and keeps both in failed_under.
