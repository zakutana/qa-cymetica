## Knowledge Summary
**App**: Cymetica EventTrader — AI-powered prediction markets / event trading platform

**Business Rules**:
- Blue Team share price + Red Team share price = $1.00 at all times
- Epoch volume (current epoch only) and chart volume (historical, timeframe-scoped) are different metrics and will legitimately differ
- Order panel Avg Price may differ slightly from the team button price due to bid-ask spread/slippage — this is expected behavior but should be labeled clearly
- Amount input field uses type=number with step=0.01 — decimal separator must be a period (.) not a comma (,) for correct parsing
- Minimum order amount is $0.10, maximum is $1,000,000
- P&L for a newly opened $0.10 position must never show a loss larger than the position size itself (e.g. -$3.15 for a $0.10 bet is impossible and is a critical calculation error)
- The valuemin attribute on the amount input must exactly equal 0.10, not 0.10000000149011612 — floating-point representation errors in HTML attributes can cause false validation rejections
- Orderbook tabs (Blue Team / Red Team) must display price data belonging to the selected team only — cross-team data leakage is a high-severity display bug
- Fill confirmation messages are transient UI state and must be cleared when the related position is closed or superseded
- Team selector toggle visual state (highlighted button) must exactly match the team data shown in the order panel — avg price, submit button label, and shares preview must all correspond to the visually active toggle
- Shares preview must always be rounded to exactly 2 decimal places (e.g. $0.10 / $0.66 ≈ 0.15 shares, not 0.2); rounding to 1dp causes material overstatement of share counts especially for small amounts
- Fill confirmation messages (e.g. 'Resting order placed') are transient state tied to the order lifecycle and must be cleared upon order cancellation — a stale message after cancellation is a UI state management bug
- Quick-select buttons (10¢, 50¢, $1) must inject period-separated decimal values into the amount input (0.10, 0.50, 1.00); injecting comma-separated values (0,10, 0,50) produces an invalid type=number field value that fails HTML5 validation
- The submit button label must always display the active team name ('Buy Blue Team' / 'Buy Red Team') regardless of whether the entered amount is negative, zero, or above maximum — inconsistent label suppression on negative input is a bug
- The win-probability chart Y-axis must never exceed 100%, because team probabilities are bounded [0, 100] and their sum equals 100%
- Negative amount inputs must be rejected gracefully: the shares preview must show 0 (not a negative share count) and the submit button label must be preserved
